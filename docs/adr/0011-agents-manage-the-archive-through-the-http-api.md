# Agents manage the archive through the HTTP API

Agents need to find, read, rename, and delete Traces, check imports, and read server logs, and this must not depend on which agent or harness is asking. All of that capability lives in the `/api/v1` HTTP API, whose contract is an OpenAPI document the server publishes. Other surfaces are thin consumers: first a Traicr Executor app that generates its tools from that document, which any MCP-capable agent can reach, and later `traicr` CLI subcommands for machines without MCP or Executor. A Traicr-native MCP server was rejected because it would duplicate the Executor app's tool definitions and auth. A markdown API reference was rejected because it would be a second description of the API that Executor cannot use.

Agents use the existing admin token. `traicr login` already stores it on every Source Machine, so one more trusted holder adds little risk; if it leaks, it is rotated, every machine logs in again, and browser sessions end. Scoped or revocable tokens were deferred until a less-trusted client needs them. Agents may delete Traces, and the Executor app requires an approval for each delete, so the server needs no separate permission for it.
